狀態：2026-09-26 確認，逐頁原型製作中。確認後，這份文件與 `docs/design/subs-tracker-design.html` 的原型就是實作規格。實作時發現規格有漏洞，先改這份文件，再改程式。

依據：

- `PRODUCT.md`
- 視覺方向：錢包卡匣（`docs/design/subs-tracker-design.html`）
- `docs/research/2026-09-26-home-and-settings-ux.md`（首頁與設定）
- `docs/research/2026-09-26-passkey-settings-ux.md`（passkey）
- 2026-09-26 的決定：總花費顯示月均與年均，依貨幣分開，試用不計入；新增提醒失敗警告、取消期限、JSON 匯出、每週付款週期

## 共通規則

- 手機優先。桌機是放大的版本，順序與流程相同，只增加欄位與側欄。
- 字體：Noto Sans TC（中文）、Barlow Semi Condensed（數字），都從 Google Fonts 載入。
- 不用 UI 套件，移除 daisyUI（2026-09-26，依據 `docs/research/2026-09-26-ui-kit.md`）。`src/style.css` 直接使用原型的 CSS，也不用 Tailwind：原型的樣式沒有使用 Tailwind 的 class，Tailwind 的 preflight 會改變原型的邊距。元件樣式以 `docs/design/subs-tracker-design.html` 為準；對話框、下拉提示、日期欄位用瀏覽器原生的 `<dialog>`、`<datalist>`、`type="date"`。
- 介面用語：「通知管道」（取代「渠道」）、「下次扣款日」（取代「到期日期」）。
- 主題：預設跟隨系統，可在設定頁切換。只存在瀏覽器，不存到伺服器。
- 確認刪除用頁面內的確認，不用瀏覽器的 `confirm()`。
- 離線時顯示最後一次取得的資料，頂部列下方顯示「離線中，顯示 9/26 09:12 的資料」。離線時新增、編輯、刪除、儲存設定的按鈕停用，並說明「連上網路後才能修改」。
- 操作結果用 toast 告知，文字寫出做了什麼，例如「已儲存 Netflix」。

## 1. 登入（`/`）

內容：

- 名稱 SubsTracker。
- 使用者名稱、密碼、「登入」。
- 有註冊 passkey 時，瀏覽器的自動填入會提供 passkey（conditional UI），另有「使用 passkey 登入」按鈕。

狀態：

- 帳密錯誤：欄位下方顯示「使用者名稱或密碼錯誤」，保留使用者名稱。
- 登入中：按鈕顯示「登入中」並停用。
- 取消 passkey 對話框：不顯示錯誤。
- 已登入時開啟：轉到首頁。

## 2. 首頁：卡匣（`/admin`）

手機，由上到下：

1. **頂部列**：左側頁面名稱「訂閱」，右側搜尋與設定兩個圖示。登出與主題切換移到設定頁。
2. **提醒警告**（只在有問題時出現）：一行文字，點擊前往設定。
   - 沒有啟用任何通知管道：「沒有啟用通知管道，提醒不會送出」。
   - 上次排程有管道發送失敗：「9/26 09:00 的提醒有 1 個管道發送失敗」。
3. **花費摘要**：每種貨幣一行，「TWD 1,219 / 月 · 14,628 / 年」。超過 3 種貨幣時，其餘折疊成「另 N 種貨幣」。下方一行「另有 2 筆試用中」。
4. **卡疊**，依下次扣款日排序，分成以下幾組，空的組不顯示：
   - **需要處理**：已過下次扣款日、沒有自動續訂、未停用。放在今天線上方。
   - 今天線：「今天 9/26（六）」。
   - **7 天內**：組標題右側顯示每種貨幣的小計。
   - **30 天內**：同上。
   - **之後**：不顯示小計。
   - **已停用（N）**：折疊，點擊展開。
5. **新增按鈕**：右下角，拇指範圍內。卡疊底部留出按鈕的高度，避免遮住最後一張卡。

卡緣（56px）：名稱、金額與週期、扣款時間。30 天內顯示「N 天後」，更遠的顯示日期。例外時才加標籤：「試用」「手動續訂」「未設提醒」。在提醒天數內的卡，倒數改成粗體。

展開的卡（一次只展開一張）：

- 已停用與已過期的卡用不透明的混色變淡，不用 `opacity`：卡片互相重疊，半透明會讓後面的卡透出來。
- 動畫：點卡緣後，卡片向下滑開，下方的卡跟著往下移；原本展開的卡同時收合。高度 280ms、內容淡入，使用 ease-out 曲線。展開的卡超出畫面時，捲動到完整可見。系統設定「減少動態效果」時不播放動畫。

- 金額與週期、下次扣款日與倒數。試用的卡顯示「試用結束」。
- 分類、付款方式、提醒天數。設了取消期限時，顯示「10/1 前取消」。
- 有網站時顯示「前往網站」。
- 操作：「編輯」；「已續訂」（只在手動續訂的卡出現，把下次扣款日推進一個週期）；「停用」或「啟用」。
- 不再有每張卡的「測試通知」。測試改在設定頁的每個管道。

搜尋：點搜尋圖示後，頂部列變成搜尋框，下方是分類選項。卡疊即時篩選，比對名稱、分類、備註。

空狀態：一句說明「還沒有訂閱。新增第一筆，扣款前會收到提醒。」與「新增訂閱」按鈕。

桌機（≥ 1024px）：

- 左側 2/3 是同一份卡疊，卡緣多出分類、付款方式、週期欄位。
- 右側 1/3 是側欄：花費摘要、每種貨幣各自的分類月均長條圖、提醒狀態（每日提醒時間、時區、啟用的管道、上次執行時間與結果）。
- 頂部列直接顯示搜尋框與「新增訂閱」按鈕，不用浮動按鈕。

## 3. 新增與編輯訂閱

手機是全螢幕的頁面，桌機是右側滑出的面板。新增與編輯共用一個表單。

主要欄位（永遠顯示）：

- 名稱（必填）
- 金額（必填）與貨幣。貨幣預選上一次使用的貨幣。
- 付款週期：每 N 天、週、月、年。
- 下次扣款日（必填）。打開「試用中」時，標籤改為「試用結束日」。
- 自動續訂（開關）。
- 試用中（開關）。
- 提醒：「沿用預設（3 天前）」「不提醒」「1 天前」「3 天前」「7 天前」「14 天前」「30 天前」。
- 取消期限（選填日期）。設了這個日期時，提醒依這個日期計算。

「更多」區塊（預設收合）：

- 分類：輸入時提示已經用過的分類。
- 付款方式：自由輸入，例如「玉山 Pi 卡」。輸入時提示已經用過的付款方式。
- 網站
- 開始日
- 備註

底部：

- 「儲存」。
- 編輯時多一個「刪除訂閱」，按下後在按鈕位置顯示確認。

移除的欄位：

- 「續訂/終止日期」開關。現在取消勾選後表單不要求日期，但 API 仍然要求，所以存不進去。
- 「設定提醒」勾選框。併入「提醒」選單。

驗證：錯誤顯示在欄位下方，寫出原因與修正方式，例如「請輸入數字，例如 390」。

## 4. 設定（`/admin/config`）

一整頁，不分分頁，由上到下：

1. **提醒**
   - 每日提醒時間（00:00–23:00）
   - 時區
   - 預設提前天數
   - 提醒頻率：「只提醒一次」「每天提醒直到扣款」
2. **通知管道**
   - 沒有啟用任何管道時，這一段最上方顯示警告。
   - Telegram、Email、Bark、Webhook 各一列，右側顯示「已啟用」「未設定」或「發送失敗」。點開後依序是：開關、必要欄位、「進階」折疊區、「傳送測試」。
   - 進階欄位：Webhook 的方法、標頭、內容範本；Bark 的伺服器、保存歷史、查詢參數；Email 的寄件人名稱。
3. **帳號與登入**
   - 使用者名稱
   - 修改密碼：新密碼、確認新密碼
   - Passkey，見第 5 節
   - 登出
4. **資料**
   - 「匯出 JSON」：下載所有訂閱與設定，不含密碼雜湊、JWT 金鑰與通知管道的憑證。
5. **外觀**
   - 主題：「跟隨系統」「淺色」「深色」。

每一段各自儲存，按鈕在段落底部；有未儲存的修改時，按鈕才可以按。

## 5. Passkey（設定頁的一段）

- 清單的每一筆：
  - 名稱。預設是驗證器的提供者名稱，例如「iCloud 鑰匙圈」，可以改名。
  - 建立時間、最後使用時間。
  - 「已同步」或「僅限此裝置」。
- RP ID 與目前網址不同的 passkey，標示「在此網址無法使用」。
- 「新增 passkey」「刪除」與「帳號與登入」的修改需要 10 分鐘內登入過；超過時 API 回傳 403 與 `REAUTH_REQUIRED`，頁面要求輸入密碼或完成一次 passkey 驗證（再登入一次），成功後重試。改名不需要。
- 刪除最後一個 passkey 前，提示之後只能用密碼登入。
- 移除全部 10 個 WebAuthn 技術選項。

## 6. 資料與 API 需求

### 儲存

- D1（binding `DB`）是唯一的儲存（2026-09-26 決定，依據 `docs/research/2026-09-26-kv-vs-d1.md`）。資料表：`settings`（一列）、`notification_channels`、`subscriptions`、`reminder_deliveries`、`cron_runs`、`passkey_credentials`、`webauthn_challenges`。
- KV 不再寫入，只作為舊資料的匯入來源。第一次讀取設定時，若 `settings` 沒有資料，就在一個 `batch()` 內匯入 KV 的舊資料，重複執行不會重複寫入。
- 使用者擁有的欄位與 Cron 擁有的欄位分開。Cron 的更新帶條件（`expiry_date`、`updated_at` 沒被使用者改過），不會蓋掉使用者的修改。

實作時一次改完，不再依畫面逐步追加。已經 commit 的變更也列在這裡核對。

### 新的持久狀態

- **排程結果**：每次 Cron 在 `cron_runs` 新增一列；各管道的結果寫入 `reminder_deliveries` 與 `notification_channels.last_status`。首頁警告與桌機側欄讀最近一次 `cron_runs` 與失敗的管道。「傳送測試」的結果不寫入 `last_status`，避免蓋掉真實的失敗狀態。
- **Passkey**：`rp_id`、`aaguid`、`last_used_at`、`backed_up` 是 `passkey_credentials` 的欄位；固定的 user handle 存在 `settings.webauthn_user_handle`。細節見 passkey 研究第 7.4 節。
  - RP ID 沿用舊版的可註冊網域（`psl.get(主機名稱)`），不採用研究建議的完整主機名稱：改用主機名稱會讓升級前的 passkey 全部不能使用。預期 origin 取自請求網址（`new URL(c.req.url).origin`），其他子網域取得的 assertion 會被拒絕（WebAuthn §13.4.9）。
  - 提供者名稱只對照研究第 5.4 節查證過的 4 個 AAGUID；AAGUID 對照表的授權未確認，不整份打包。

### 離線

- 沿用現有的 PWA：`public/manifest.webmanifest`、`public/sw.js`、`src/client/registerSW.ts`。頁面與靜態檔已經有快取，目前缺的是 API 資料。
- `manifest.webmanifest` 的 `theme_color`、`background_color` 改成新設計的顏色。
- App 圖示改用 `docs/design/icons/` 的新圖示：`icon.svg`、`favicon.svg`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png`，取代 `public/` 的舊檔。
- `public/sw.js` 對 `GET /api/subscriptions` 與 `GET /api/settings` 改用「先網路，失敗時用快取」，並記錄快取時間。
- 頁面依回應是否來自快取，顯示離線提示並停用修改。

### 合計的算法

- 只加總使用中、非試用、未停用的訂閱，依貨幣分開。
- 每年金額：每 N 天 × 365 ÷ N、每 N 週 × 52 ÷ N、每 N 月 × 12 ÷ N、每 N 年 ÷ N。
- 每月金額 = 每年金額 ÷ 12。
- 7 天內、30 天內的組小計是這段期間實際會扣的金額，不是平均值。
