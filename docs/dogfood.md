# Dogfood 清單

UI 重構、流程調整、套件升級之後，以及每次發布之前，照本清單實際操作一次 app。清單會重複使用：執行後保留項目，只在執行紀錄加一列。流程改變時，同步更新對應的步驟。

## 準備

- 用 `bun run preview`，不用 `bun run dev`。preview 執行的是部署用的打包產物，service worker 也只在打包後註冊。
- 用全新的本機資料：在乾淨的 clone 中執行，或先刪除 `.wrangler/`，再執行 `bun run db:migrate:local`。全新安裝的帳密是 `admin` / `password`（`src/services/legacyImport.ts`）。
- 開啟瀏覽器開發者工具。每一步都確認 console 沒有錯誤。
- 手機寬度（約 390px）與桌機寬度（1024px 以上）各執行一次，淺色與深色主題各看一次。

## 1. 登入（`/`）

- [ ] 輸入錯誤的帳密：欄位上方顯示「使用者名稱或密碼錯誤」，保留使用者名稱。
- [ ] 輸入正確的帳密：按鈕顯示「登入中」，轉到 `/admin`。
- [ ] 已登入時開啟 `/`：轉到 `/admin`。
- [ ] 沒有 passkey 時：不顯示「使用 passkey 登入」。

## 2. 首頁卡匣（`/admin`）

- [ ] 卡疊依下次扣款日分成「需要處理」「7 天內」「30 天內」「之後」「已停用」；今天線在「需要處理」下方。
- [ ] 7 天內、30 天內的組標題顯示每種貨幣的小計；花費摘要依貨幣分開，試用不計入。
- [ ] 點卡緣：卡片滑開，原本展開的卡收合。系統開啟「減少動態效果」時沒有動畫。
- [ ] 手動續訂的卡按「已續訂」：下次扣款日推進一個週期，toast 寫出新日期。
- [ ] 停用與啟用：卡片移到「已停用」或移回原本的組，重新整理後仍維持。
- [ ] 搜尋：比對名稱、分類、付款方式、備註；分類選項可以篩選；沒有結果時顯示說明。
- [ ] 沒有啟用通知管道、或上次提醒有管道失敗時：頂部顯示警告，點擊前往設定。
- [ ] 桌機：右側欄顯示花費、分類長條圖、提醒狀態；頂部列有搜尋框與「新增訂閱」。

## 3. 新增與編輯訂閱

- [ ] 按「新增訂閱」：手機是全螢幕，桌機從右側滑出；焦點在「名稱」。
- [ ] 在「名稱」與「金額」逐字輸入：每個字都輸入進去，焦點留在欄位，表單不閃動。
- [ ] 必填欄位留空後儲存：欄位下方顯示原因，焦點移到第一個錯誤的欄位。
- [ ] 填寫所有欄位（包含「更多」裡的欄位）後儲存：卡疊出現新卡並展開，toast「已儲存 …」。
- [ ] 打開「試用中」：日期標籤變成「試用結束日」，預覽卡顯示「試用」。
- [ ] 日期欄位：手機點欄位在下方展開月曆；桌機的月曆浮在內容上，表單不出現新的捲軸，下方空間不夠時往上彈出，捲動表單時跟著欄位移動。今天標成紅色。方向鍵移動日期，PageUp／PageDown 換月，Enter 選取；年與月的選單可以跳到其他年月。Esc 只關閉月曆，不關閉表單；點月曆外面也會關閉。
- [ ] 編輯後在取消期限的月曆按「清除」並儲存：重新整理後取消期限不見了。
- [ ] 刪除：按鈕位置顯示確認，確認後卡片消失。按 Esc 或返回鍵關閉表單。

## 4. 設定（`/admin/config`）

- [ ] 每一段只有在修改後才能儲存；儲存後顯示「已儲存」，重新整理後值仍然存在。
- [ ] 通知管道：啟用但缺少必要欄位時，錯誤訊息寫出欄位名稱。「傳送測試」使用尚未儲存的值。
- [ ] 修改密碼：兩次輸入不同或少於 8 個字元時提示原因。儲存後登出，用新密碼可以登入，舊密碼不行。
- [ ] 匯出 JSON：下載 `subs-tracker-<日期>.json`，內容沒有密碼雜湊、JWT 金鑰與管道憑證。
- [ ] 外觀：切換主題後重新整理，主題仍然套用；只影響這個瀏覽器。
- [ ] 登出：回到登入頁。再開啟 `/admin`，轉回登入頁。

## 5. Passkey（需要真實的驗證器）

- [ ] 新增 passkey：清單顯示提供者名稱（例如「iCloud 鑰匙圈」）、建立時間、「已同步」或「僅限此裝置」。
- [ ] 登入超過 10 分鐘後新增或刪除 passkey：顯示重新驗證；輸入密碼或改用 passkey 確認後，原本的動作繼續完成。密碼錯誤時顯示原因，不轉到登入頁。
- [ ] 修改名稱：不需要重新驗證。清空名稱後恢復提供者名稱。
- [ ] 登出後：登入頁的使用者名稱欄位提供 passkey 自動填入；「使用 passkey 登入」按鈕也能登入。取消對話框時不顯示錯誤。
- [ ] 刪除最後一個 passkey：確認文字寫出之後只能用密碼登入。

## 6. 離線

- [ ] 開啟首頁與設定頁各一次後中斷網路，重新整理：顯示「離線中，顯示 … 的資料」，新增、編輯、儲存的按鈕停用。
- [ ] 恢復網路後重新整理：離線提示消失。
- [ ] 登出後，開發者工具的 Cache Storage 沒有 `/api/settings` 與 `/api/subscriptions`。

## 7. 通知與 Cron

- [ ] 在設定頁設定測試用的通知管道（Telegram、Bark、Webhook、Email），每個管道按「傳送測試」都收到訊息。
- [ ] 把每日提醒時間設成目前的小時，新增一筆在提醒天數內的訂閱，再開啟 `/cdn-cgi/handler/scheduled`：已啟用的管道收到提醒；首頁桌機側欄的「上次執行」更新。

## 8. 部署

- [ ] `bun run deploy`：輸出顯示 D1 migration 已套用，Worker 部署成功。
- [ ] 在 workers.dev 網址重新執行第 1–7 節。
- [ ] 在 Cloudflare Dashboard → Workers → Triggers → Cron Triggers 按「Trigger Now」：已啟用的管道收到提醒。
- [ ] `wrangler tail` 沒有未捕捉的錯誤。

## 9. 目標瀏覽器

- [ ] 在使用者實際使用的瀏覽器上執行第 1–6 節。Vite 8 預設的 build target 是 Chrome 111、Safari 16.4 等較新的版本。
