# Dogfood 清單

UI 重構、流程調整、套件升級之後，以及每次發布之前，照本清單實際操作一次 app。清單會重複使用：執行後保留項目，只在執行紀錄加一列。流程改變時，同步更新對應的步驟。

## 準備

- 用 `bun run preview`，不用 `bun run dev`。preview 執行的是部署用的打包產物，有些錯誤只在打包後出現。
- 用全新的本機 KV：在乾淨的 clone 中執行，或先刪除 `.wrangler/`。全新 KV 的管理員帳密見 `src/services/config.ts` 的 `DEFAULT_CONFIG`。
- 開啟瀏覽器開發者工具。每一步都確認 console 沒有錯誤。

## 1. 登入

- [ ] 輸入錯誤的帳密：顯示錯誤訊息，停在登入頁。
- [ ] 輸入正確的帳密：轉到 `/admin`。
- [ ] 已登入時開啟 `/`：轉到 `/admin`。
- [ ] 登出：回到登入頁。再開啟 `/admin`，轉回登入頁。

## 2. 訂閱管理（`/admin`）

- [ ] 新增訂閱並填寫所有欄位（週期、付款方式、提醒）：列表出現新訂閱，欄位值正確。
- [ ] 必填欄位留空後送出：顯示驗證錯誤，沒有新增資料。
- [ ] 編輯訂閱：重新整理頁面後，修改的值仍然存在。
- [ ] 停用與啟用：狀態切換後，重新整理頁面仍維持。
- [ ] 刪除訂閱：確認對話框出現，確認後訂閱從列表消失。
- [ ] 圖示：新增、編輯、刪除、選單、主題切換的圖示都正常顯示。

## 3. 設定頁（`/admin/config`）

- [ ] 載入頁面：每個欄位都填入目前的設定，包含時區、通知時段、各通知渠道、WebAuthn。
- [ ] Bark「保存推送」：分別存成勾選與不勾選，重新整理後狀態正確。
- [ ] WebAuthn hints：勾選部分選項並儲存，重新整理後勾選狀態正確。
- [ ] 修改其他設定並儲存：重新整理後值仍然存在。
- [ ] 修改管理員密碼：登出後，用新密碼可以登入，舊密碼不行。

## 4. Passkey（需要真實的驗證器）

- [ ] 在設定頁啟用 WebAuthn，註冊 passkey：清單顯示名稱、建立時間、傳輸方式，以及編輯與刪除按鈕。
- [ ] 修改 passkey 名稱：清單顯示新名稱。
- [ ] 登出後用 passkey 登入：轉到 `/admin`。
- [ ] 在註冊對話框按取消：顯示「註冊已取消」。在登入對話框按取消：不顯示錯誤。
- [ ] 刪除 passkey：清單變成空狀態，空狀態的圖示正常顯示。

## 5. 通知與 Cron

- [ ] 在設定頁設定測試用的通知渠道（Telegram、Bark、Webhook、Email）。
- [ ] 在訂閱列表按「測試通知」：每個已啟用的渠道都收到訊息。
- [ ] 新增一筆即將到期並開啟提醒的訂閱，再開啟 `/cdn-cgi/handler/scheduled`：log 顯示任務開始、讀到訂閱、任務完成，已啟用的渠道收到提醒。
- [ ] 設定 `API_TOKEN` 後呼叫 `POST /api/notify/{token}`：正確的 token 會發送通知，錯誤的 token 被拒絕。沒有設定 `API_TOKEN` 時，這個 API 停用。

## 6. Staging

- [ ] 部署到 staging。使用 `@cloudflare/vite-plugin` 時，環境可能要在 build 時用 `CLOUDFLARE_ENV=staging` 指定；`wrangler deploy --env staging` 能否使用還沒驗證。
- [ ] 在 staging 網址重新執行第 1–5 節。
- [ ] 在 Cloudflare Dashboard → Workers → Triggers → Cron Triggers 按「Trigger Now」：已啟用的渠道收到提醒。
- [ ] `wrangler tail --env staging` 沒有未捕捉的錯誤。

## 7. 目標瀏覽器

- [ ] 在使用者實際使用的瀏覽器上執行第 1–3 節。Vite 8 預設的 build target 是 Chrome 111、Safari 16.4 等較新的版本。
