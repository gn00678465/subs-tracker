# UI 元件層研究：shadcn/ui、shadcn 風格套件、daisyUI 5、不使用套件

- 查核日期：2026-09-26
- 範圍：重新設計（`docs/design/subs-tracker-design.html`，卡匣式卡片堆疊）時，元件層要改用 shadcn/ui 或 shadcn 風格的套件，還是保留 daisyUI 5，或不使用套件。
- 需要的通用元件：按鈕、輸入欄位、下拉選單、分段選擇、開關、對話框／底部面板、toast、確認對話框、日期輸入、分類 combobox。卡匣、今日線、設定列是自訂元件，不論選哪個方案都要自己寫。
- 標記：
  - 【查證】：來自官方文件、套件原始碼、npm registry 或 GitHub API。
  - 【實測】：在 scratchpad 目錄（專案之外）建立測試專案並實際執行。本 repo 除了本文件以外，沒有任何檔案變更。
  - 【推論】：依據上述證據推導，沒有直接驗證。
- 實測環境：Vite 8.3.1、Tailwind CSS CLI 4.3.3、bun、Google Chrome 154.0.8037.57（headless）、happy-dom 20.14.5。

## 1. 摘要與建議

### 1.1 最重要的發現

1. **shadcn/ui 只能用在 React 專案。** 每個元件都是 `.tsx` 原始碼，開頭是 `"use client"` 與 `import * as React from "react"`，並依賴 Base UI、Radix 或 React Aria（`apps/v4/registry/bases/base/ui/dialog.tsx`）。【查證】2026-07-02 起新專案預設用 Base UI。【查證】
2. **Hono 的 `hono/jsx/dom` 不能取代 React 執行 shadcn 的底層元件。** 把 `react` alias 到 `hono/jsx/dom` 後：
   - Radix Dialog 可以開啟，但 trigger 的 `aria-expanded` 不正確（關閉時沒有屬性，開啟時是空字串），在 Chrome 中焦點沒有移入對話框，按 Escape 也沒有關閉。【實測】
   - Base UI Dialog 在執行時丟出 `TypeError: Cannot set properties of undefined (setting 'current')`，對話框無法開啟。【實測】
   - 原因之一：`hono/jsx/dom` 把 `aria-expanded={false}` 移除，把 `{true}` 輸出成 `""`（`hono/dist/jsx/dom/render.js:119-121`）。React 會輸出 `"false"`／`"true"`。【查證＋實測】
3. **改用 shadcn/ui 會讓客戶端 JS 變成約 4.5 倍。** 只有一個 Dialog 的 React＋Radix bundle 是 91.22 kB（gzip），React＋Base UI 是 100.46 kB。目前整個客戶端的 JS 合計約 25.7 kB（gzip）。【實測】
4. **Franken UI 已停止維護。** GitHub README 在 2026-06-11 改成「Franken is now 0build」。它的後繼專案 Frankenstyle 也同時停止。0build 在 2026-06-06 建立，27 個 star，沒有任何 GitHub release。【查證】
5. **Basecoat 是目前唯一可驗證、有維護、不需要 React 的 shadcn 風格套件。** 1.0.0 在 2026-06-27 發布，MIT 授權，需要 Tailwind v4。但它沒有分段選擇與日期選擇器，combobox 不能輸入清單以外的值，並且預設把全部元件的 CSS 都輸出（約 22 kB gzip），不論頁面有沒有使用。【查證＋實測】
6. **daisyUI 5 的元件樣式放在 `@layer utilities` 內的巢狀 layer。** 寫在 `@layer components` 的自訂樣式，即使 specificity 較高，也會輸給 daisyUI。在 Chrome 實測：`.btn.in-components`（`@layer components`）沒有生效；未分層的規則與直接寫在 `@layer utilities` 的規則有生效。【查證＋實測】
7. **設計稿的 class 名稱與 daisyUI 衝突。** 設計稿使用 `.btn`、`.btn-primary`、`.btn-secondary`、`.input`、`.select`、`.card`、`.status`、`.fab`，這些都是 daisyUI 的元件名稱。daisyUI 5 依原始碼中出現的 class 輸出樣式，所以兩者並存時，daisyUI 的樣式會套到新的標記上。【查證＋推論】

### 1.2 建議做法

**不使用元件套件：Tailwind v4 加上自己的一小組元件，在重新設計的過程中移除 daisyUI。** shadcn/ui 不採用。

理由：

- 設計稿已經用自己的 token（`--ground`、`--surface`、`--ink`、`--line`、`--today`、8 個分類色、`--radius-card`、`--radius-control`）寫好按鈕、欄位、分段選擇、開關、設定列的 CSS。套件提供的部分主要是這些元件的外觀，而外觀會被設計稿全部重寫。【推論】
- 其餘行為可以用原生元素完成：`<dialog>`、`<details>`、`<input type="date">`、`<input list>`＋`<datalist>`、`<input type="checkbox" role="switch">`。專案已經有自己的 toast（`src/utils/toast.ts`）與確認對話框（`src/utils/confirmDialog.ts`），只需要改樣式。【查證＋推論】
- 專案已經在客戶端使用 `hono/jsx/dom` 產生表格（`src/client/admin/tableRenderer.tsx`），不需要另一個元件執行環境。【查證】
- 重新設計本來就會改寫每一頁的標記。在同一次工作中移除 daisyUI，額外成本很低，並且消除 1.1 第 6、7 點的衝突。【推論】

如果之後仍想使用套件，第二選擇是保留 daisyUI 5，但只用 `include` 載入少數元件，並把設計稿的 token 對應到 daisyUI 的主題變數（第 5 節）。

## 3. shadcn/ui

### 3.1 版本與執行需求

- CLI 套件：`shadcn` 4.21.0，MIT。【查證，npm registry】
- 手動安裝的相依套件：`shadcn class-variance-authority cn lucide-react tw-animate-css`，另外要 `components.json`、import alias 與一份 `globals.css`（`@import "tailwindcss"`、`@import "tw-animate-css"`、`@import "shadcn/tailwind.css"`、`@custom-variant dark (&:is(.dark *))`、`@theme inline`）。【查證，`apps/v4/content/docs/installation/manual.mdx`】
- 2026-09-03 起，元件從 `cn` 套件匯入 `cn`，取代 `clsx`＋`tailwind-merge`。`cn` 0.4.0 的描述是「Drop-in replacement for clsx + tailwind-merge」。【查證，`changelog/2026-09-cn.mdx`、npm】
- 底層元件庫可以選三種：
  - Base UI：2026-07-02 起是預設（「New projects now use Base UI by default. Radix is still fully supported.」）。`@base-ui/react` 1.8.0 的 peer 是 `react ^17 || ^18 || ^19`、`react-dom`、`date-fns ^4`、`@date-fns/tz`。【查證】
  - Radix：`radix-ui` 1.6.7，peer 是 `react`、`react-dom`。【查證】
  - React Aria：2026-07-17 加入（`--base aria`）。【查證】
- Tailwind v4：文件寫「All components are updated for Tailwind v4 and React 19」，顏色改用 OKLCH，每個元件有 `data-slot` 屬性。【查證，ui.shadcn.com/docs/tailwind-v4】
- 安裝方式：CLI 把元件原始碼複製到專案內，之後由專案自己維護。CLI 內建的框架偵測只有 `next-app`、`vite`、`astro`、`laravel`、`react-router`、`tanstack-start`，其他情況走 `manual`。Hono 不在清單內。【查證，`shadcn/dist/index.js`】
- 暗色模式：以 `.dark` class 切換。本專案用 `data-theme` 屬性。【查證】

### 3.2 `hono/jsx/dom` 能否執行 shadcn 的元件

`hono/jsx/dom` 有 React 相容的 API：`Children`、`cloneElement`、`createPortal`、`flushSync`、`forwardRef`、`useId`、`useSyncExternalStore` 等都有匯出（`hono/dist/jsx/dom/index.js`）。【查證】Hono 文件說這些 hook「compatible or partially compatible with React」。【查證，hono.dev/docs/guides/jsx-dom】

Hono 的 issue #2508（2024-04）記錄：用 Vite alias 把 `react` 指向 `hono/jsx/dom` 時，React DnD 可以用，但 react-toastify、spinners-react、Radix UI Primitives 都失敗。該 issue 在 2024-06-23 關閉，維護者寫「This was fixed though there may be some backlogs」。【查證】

本研究用目前的版本重新測試。設定：Vite alias `react`、`react-dom`、`react/jsx-runtime`、`react-dom/client` 到 `hono/jsx/dom` 對應的路徑，渲染一個 Dialog（Trigger、Portal、Overlay、Content、Title、Description、一個 input、Close），點擊 trigger，再對焦點元素送出 Escape。

| 組合                              | 建置 | trigger `aria-expanded`（關／開） | 開啟 | 焦點移入對話框 | Escape 關閉          | 錯誤                                                                |
| --------------------------------- | ---- | --------------------------------- | ---- | -------------- | -------------------- | ------------------------------------------------------------------- |
| React 19.3.0＋Radix Dialog 1.1.23 | 成功 | `"false"`／`"true"`               | 是   | 是             | 是，焦點回到 trigger | 無                                                                  |
| Hono 4.13.9＋Radix Dialog         | 成功 | 沒有屬性／`""`                    | 是   | 否（Chrome）   | 否（Chrome）         | 無                                                                  |
| React 19.3.0＋Base UI 1.8.0       | 成功 | `"false"`／`"true"`               | 是   | 是             | 否（見下方說明）     | 無                                                                  |
| Hono 4.13.9＋Base UI              | 成功 | 沒有屬性                          | 否   | —              | —                    | `TypeError: Cannot set properties of undefined (setting 'current')` |

【實測，Chrome 154 headless】說明：

- React＋Base UI 在測試中沒有被 Escape 關閉。測試是用程式送出的 `KeyboardEvent`，不是真正的按鍵。這個結果只表示測試方法的限制，不能當作 Base UI 的缺陷。
- 在 happy-dom 中，Hono＋Radix 的焦點與 Escape 都正常，只有 `aria-expanded` 錯誤。Chrome 的結果較可信。
- 結論：`hono/jsx/dom` 可以建置並渲染 Radix 的部分元件，但無障礙屬性與焦點管理不正確；Base UI 無法執行。shadcn 的元件要正確運作，必須使用 React。

### 3.3 `hydrateRoot` 不是真正的 hydration

`hono/jsx/dom/client` 的 `hydrateRoot` 實作是先 `createRoot`，再 `root.render(reactNode)`（`hono/dist/jsx/dom/client.js:40-44`）。它會重新產生 DOM，不會接手伺服器產生的 DOM。【查證】所以「伺服器用 Hono JSX 產生頁面、客戶端用 `hono/jsx/dom` hydrate shadcn 元件」這條路不存在。【推論】

### 3.4 在本專案採用 shadcn/ui 的做法與代價

可行的做法有兩種：

1. **整個前端改成 React。** 伺服器端用 `react-dom/server`。`react-dom` 19.3.0 的 `exports` 有 `workerd` 條件，指向 `server.edge.js`（提供 `renderToReadableStream`）。【查證】Hono 另有 `@hono/react-renderer` 1.0.1（最後更新 2025-04-11，peer `react ^19`）。【查證】客戶端要 hydrate 整頁，或做 islands。
2. **伺服器端維持 Hono JSX，只在客戶端掛載 React islands。** 每個有互動的區塊（表單對話框、combobox、toast）用 React `createRoot` 掛載。伺服器端無法先產生這些區塊的 HTML。【推論】

兩種做法都需要：

- 把 `src/pages`、`src/components`、`src/client` 的相關程式（合計約 3,335 行）改寫成 React 元件。Hono JSX 用 `class`，React 用 `className`；目前的 DOM 操作式客戶端腳本（例如 `src/client/admin/index.ts` 的 `setFormValue`、`innerHTML`）要改成 React 狀態。【查證＋推論】
- 把 `lucide`（`data-lucide`＋`createIcons`）換成 `lucide-react`。【推論】
- 客戶端 JS 增加約 90–100 kB（gzip）。量測方式：Vite 8.3.1 library 模式、壓縮後，只有一個 Dialog。React＋Radix：348.96 kB（gzip 91.22 kB）；React＋Base UI：383.10 kB（gzip 100.46 kB）。目前全部客戶端 JS 約 25.7 kB（gzip）。【實測】
- 單一使用者、以手機 PWA 為主的產品，首次載入與更新都要下載這些 JS。【推論】

工作量估計：8–15 人天（改寫三個頁面與客戶端腳本、建立 React SSR 或 islands 管線、重新做 dogfood 流程）。【推論】卡匣、今日線、設定列仍然要自己寫，shadcn 沒有這些元件。【推論】

### 4.2 Franken UI

### 5.3 主題能否承載卡匣設計

主題變數（`node_modules/daisyui/theme/light.css`）：`--color-base-100/200/300`、`--color-base-content`、`--color-primary` 等 8 組語意色與各自的 `-content`、`--radius-selector`、`--radius-field`、`--radius-box`、`--size-selector`、`--size-field`、`--border`、`--depth`、`--noise`。【查證】

可以對應的部分【推論】：

| 設計稿 token       | daisyUI 變數                                                                     |
| ------------------ | -------------------------------------------------------------------------------- |
| `--surface`        | `--color-base-100`                                                               |
| `--ground`         | `--color-base-200`                                                               |
| `--line`           | `--color-base-300`                                                               |
| `--ink`            | `--color-base-content`、`--color-primary`（主要按鈕是墨色）                      |
| `--danger`         | `--color-error`                                                                  |
| `--radius-control` | `--radius-field`（10px）                                                         |
| `--radius-card`    | `--radius-box`（14px）                                                           |
| 觸控高度 44px      | `--size-field: 0.275rem`（按鈕高度是 `--size-field × 10`，`button.css`）【查證】 |
| 平面外觀           | `--depth: 0`、`--noise: 0`                                                       |

無法對應的部分：

- `--today`、`--focus`、`--ink-2`、`--ink-3` 與 8 個分類色沒有對應的 daisyUI 變數，仍要自己定義。【推論】
- 暗色模式：daisyUI 的 `--prefersdark` 輸出 `@media (prefers-color-scheme:dark){:root:not([data-theme]){…}}` 與 `[data-theme=dark]`。設計稿用相同的 `data-theme` 機制，可以相容。【實測】但 `Layout.tsx` 目前固定輸出 `data-theme="light"`，系統暗色設定不會生效。【查證】

會和設計稿衝突的部分：

1. **Cascade layer。** daisyUI 的元件寫在 `@layer utilities { @layer daisyui.l1.l2.l3 { … } }`（`components/button.css`）。【查證】依 CSS Cascade Level 5，同一個 layer 內沒有子 layer 的規則，優先於巢狀子 layer 的規則。Chrome 實測結果：
   - `@layer components { .btn.in-components { … } }`：沒有生效（specificity 較高也一樣）。
   - `@layer utilities { .x-util { … } }`：有生效。
   - 未分層的 `.btn.unlayered { … }`：有生效。【實測】

   自訂元件 CSS 不能照 Tailwind 的慣例放在 `@layer components`，否則會輸給 daisyUI。【推論】

2. **Class 名稱。** 設計稿的 `.btn`、`.btn-primary`、`.btn-secondary`、`.input`、`.select`、`.card`、`.status`、`.fab` 都是 daisyUI 元件名稱（`node_modules/daisyui/components/`）。【查證】設計稿的 `.card` 是卡匣卡片，daisyUI 的 `card` 是另一種元件。直接搬設計稿的 CSS，兩套樣式會同時套用。解法是加 `prefix`、改名，或移除 daisyUI。【推論】
3. **全域樣式。** daisyUI 的 base 會設定 `:root` 背景為 `--color-base-100`、`scrollbar-color`，以及 modal 開啟時的捲動鎖定與背景色（`base/rootcolor.css`、`rootscrollgutter.css`、`rootscrolllock.css`）。設計稿的頁面背景是 `--ground`，要覆寫或 `exclude`。【查證＋推論】
4. **預設元件外觀。** daisyUI 的 `btn` 有陰影、邊框混色（`--btn-shadow`、`--btn-border` 依 `--depth` 計算）。設計稿的三種按鈕（墨色主要、外框次要、紅字危險）要覆寫這些變數或規則。【查證＋推論】

評估：daisyUI 可以承載設計稿的顏色與圓角，但卡匣、今日線、設定列、分段選擇、combobox 都在 daisyUI 以外。留下 daisyUI 主要換到按鈕、欄位、開關、modal 的基本樣式，代價是 layer 規則、名稱衝突與兩套 token。【推論】

## 8. 建議的遷移步驟與風險

### 8.1 步驟（不使用套件方案）

1. 把設計稿的 token 移到 `src/style.css` 的 `:root`／`[data-theme]` 與 `@theme`。
2. 為新元件選不與 daisyUI 衝突的 class 名稱，或在移除 daisyUI 之前先加 `prefix: "d-"`，讓兩者可以在同一個分支內並存。
3. 逐頁改寫（首頁卡匣、新增／編輯表單、設定、登入）。每完成一頁，執行 `bun run preview` 與 `docs/dogfood.md` 的相關段落。
4. 最後一頁完成後，從 `package.json` 移除 `daisyui`，刪除 `src/style.css` 的 `@plugin` 區塊，再執行 `bun run check`、`bun run build`、完整 dogfood。
5. 更新 `AGENTS.md` 的專案說明（目前寫「Tailwind CSS v4 + daisyUI」）。

### 8.2 風險

| 風險                                        | 影響                             | 處理方式                                                               |
| ------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| 自寫對話框的焦點管理與 Escape 行為不完整    | 鍵盤與螢幕閱讀器使用者           | 使用 `<dialog>` 的 `showModal()`，它內建焦點限制與 Escape 關閉【推論】 |
| iOS 不支援 `closedby`、`interpolate-size`   | 點背景不會關閉、展開沒有高度動畫 | 點背景關閉用 JS；高度動畫用 grid `0fr`→`1fr` 或不做動畫【推論】        |
| 並存期間 daisyUI 樣式套到新標記             | 外觀錯亂                         | 步驟 2 的 prefix 或改名                                                |
| `<datalist>` 在各瀏覽器的外觀不同，無法自訂 | 分類選單外觀不一致               | 先用原生；需要時再自寫 combobox                                        |
| 通用元件由專案自己維護                      | 長期成本                         | 元件數量少（第 6.2 節），並且以原生元素為主                            |
